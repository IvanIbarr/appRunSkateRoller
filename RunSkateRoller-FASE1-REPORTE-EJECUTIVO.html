2. Cómo levantar y verificar Fase 1 en local

  1. En appRunSkateRoller: copiar .env.example a .env (REACT_APP_LAUNCH_PHASE=1). Instalar dependencias: npm install --legacy-peer-deps si npm marca conflictos de peers.
  2. Web dev: npm run web. Build: npm run web:build.
  3. API (carpeta SIIG-ROLLER-BACKEND): node src/server.js o npm start; puerto por defecto 3001. Configurar variables DB_* según tu PostgreSQL.
  4. Comprobación automática mínima (solo política de fase): npm run verify:policy.
  5. Comprobación API: con el servidor en marcha, node scripts/smoke-api.mjs o SMOKE_API_BASE=http://host:3001 node scripts/smoke-api.mjs.
  6. Verificación visual: barra sin Marketing en F1; Ruta, Chat, Historial atenuados; cintas F1; botón Registrarse en calendario muestra aviso (no inscripción en F1).

7. Qué falta (checklist breve)

  • Infra: PostgreSQL accesible y reflejado en /health como conectado (no solo API “a medias”).
  • Validación humana F1: una pasada completa de la tabla §3.1 (Ruta, Chat, Historial, Calendario, Tips, Menú, Marketing vía menú) con anotación de incidencias.
  • CI: añadir en pipeline (si existe) al menos npm run verify:policy y npm run web:build; ampliar después con lint completo y tsc global.
  • Deuda de tipos: corregir errores de npm run typecheck por archivos o módulos (servicios, Registro, etc.).
  • Registro a evento real: diseñar endpoint, modelo y UI F2+ cuando el calendario pase a “público” según plan.
  • Comercio / Recap / pagos: siguen en modo demo o parcial; no son núcleo F1 (tabla 3.a).
